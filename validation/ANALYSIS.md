# Day 8 — Run 1 Failure Analysis

## Model evaluated
- Checkpoint: backed-up Run 1 best.pt
- Model family: YOLO11n
- Inference image size: 320
- Confidence threshold: 0.25
- Matching IoU threshold used by candidate analysis: 0.50
- Validation split: 171 images, 2,780 ground-truth instances

## Evidence reviewed
A contact sheet was generated for 20 images selected across the
validation images containing candidate false negatives.

The sheet compares ground-truth annotations with Run 1 predictions.
These are visual review examples, not 20 independently verified
individual missed detections.

## Observed failure patterns

1. Crowded urban aerial scenes:
   Multiple images contain many annotated people but very few
   model predictions. This is the clearest recurring failure pattern.

2. Small or distant people:
   People occupy few pixels in several aerial scenes. Reduced input
   resolution may contribute, but this has not been isolated experimentally.

3. Scene variation:
   Misses also appear in UAV-SAR beach and mountain scenes.
   Failures are therefore not confined to urban traffic imagery.

4. Possible annotation or localization issues:
   Candidate false negatives are generated by automated box matching.
   Each candidate is not automatically a confirmed model failure.
   Individual boxes and labels require closer inspection.

## Hypotheses to test
- Increasing inference/training image size may improve small-person recall.
- A different confidence threshold may change the number of detections.
- Dataset composition and scene variation may affect generalization.

These are hypotheses, not established causes.

## Limitations
- Run 1 stopped early because CPU training was prohibitively slow.
- Baseline and Run 1 used different model sizes and image sizes, so their
  metrics are not a controlled comparison.
- The 20-image sheet does not establish a complete taxonomy of 20
  independently verified failures.
- No conclusion about unseen-test performance is made.
- The frozen unseen test set must remain unused for tuning and model selection.

## Proposed next experiment
Prepare a higher-resolution experiment on a suitable machine, then compare
against Run 1 on the same validation split using the same evaluation settings.
Record precision, recall, mAP50, mAP50-95, inference speed, and failure examples.
Do not start a long CPU run until the available compute budget is confirmed.
